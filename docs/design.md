# OPC UA Integrator

## Commissioning research and decisions

Factories use OPC UA to expose named measurements and machine states across controller brands. Ignition's Quick Client browses one level at a time and lets an integrator inspect value, quality, and time. Use that sequence for any server. Robotics companion models organize axes, power trains, and safety states in a hierarchy. Keep the full browse path available because many axes share the leaf name ActualPosition. [Ignition Quick Client](https://docs.inductiveautomation.com/docs/8.3/ignition-modules/opc-ua) · [OPC UA Robotics](https://reference.opcfoundation.org/specs/OPC-40010-1/7.2.2)

Siemens commissioning includes application certificate exchange and separate user authentication. On an observed KRC4, a reachable endpoint and a browsable tree still yielded access-denied values until DeviceConnector Advanced was installed. The controller advertised a Windows hostname while the client reached it by IP. Preserve the entered transport address, use the advertised application URI for the session, verify the peer certificate and show read quality during selection. [Siemens industrial communication](https://support.industry.siemens.com/cs/attachments/109977705/SYH_OPC_76_en-US.pdf)

Measurements and alarm events have different lifecycles. For selected scalar samples, use bounded periodic bulk reads with timestamps, including unchanged values. This provides an explicit freshness deadline and predictable load on older controllers. For events, subscribe to an explicitly chosen notifier, request retained conditions where supported and distinguish refresh from subsequent notifications. Event messages and timestamps belong in a bounded event log. Prometheus uses selected numeric or Boolean gauges with bounded identifiers. A failed read removes the value series and records quality. [OPC UA services](https://reference.opcfoundation.org/specs/OPC-10000-4/full) · [Prometheus exporters](https://prometheus.io/docs/instrumenting/writing_exporters/)

## Screen and interaction plan

1. The first screen offers **Connect a controller**. Use a single connection per installation for the initial release. Prompt for the endpoint, display the fingerprint from discovery, and ask the administrator to compare it on the controller. A downloadable application certificate supports servers with a client trust list. A changed certificate pauses the connection until explicitly trusted.
2. **Channels** opens at Objects. Expand folders one level at a time, search within the open folder, inspect values and stage channels across folders and save the selection together. Keep selections visible while navigating. Suggest a metric suffix from the path, with an editable name for repeated equipment and units. Experienced integrators can inspect a NodeId directly and set the read interval. Store the namespace URI alongside each identifier.
3. **Overview** shows the current connection, channel values, OPC quality, last sample and last successful scrape. Present a direct recovery action for inaccessible nodes, denied credentials and disconnected controllers. Keep the monitoring view available to ordinary Edge users. Configuration belongs to an Edge administrator or owner.
4. **Events** lets an administrator select a browsed notifier. Show the source, event code, text, severity, retained flag, controller time and Box receipt time. Keep initial retained conditions distinguishable even if the controller clock is offset. Use bounded, in-memory event history.
5. **Prometheus** shows metric names, valid output and last scrape. Use the JavaScript SDK to submit bounded snapshots to Edge. DevicePlatform provisions a single authenticated Prometheus job. Existing external collectors can request a separate read-only credential. Existing Box access grants, core network policy and controller configuration stay under their respective owners.
6. Use the approved OrendaBox OEM wordmark, locally packaged Montserrat, the native dark olive navigation rail and lime actions, 44 px controls, persistent labels, visible keyboard focus and responsive one-column layouts. Preserve inputs across errors. Keep engineering details in expandable controls. Empty states link to the next concrete action.

## Qualification and release

Use a real protocol mock with secure discovery, an axis, a Boolean stop state, an unsupported text channel and an event notifier. Exercise actual reads and alarms, certificate approval, disconnection, restart, metric removal, and Edge roles. Run a real Prometheus scrape and PromQL readback. Exercise commissioning in a browser, including a narrow viewport. Build and test the release on Linux ARM64, pin the public image digest and verify the marketplace entry. Physical KRC4 qualification resumes when the controller is available.
